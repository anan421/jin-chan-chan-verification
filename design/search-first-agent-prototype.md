## 测了什么

考题是 S4–S5（2025–2026 年）里模型能分类的 83 条动作。

这次跑了其中 24 道（子集），不是全 83 道。

子集的构成：S4 有 13 道，S5 有 11 道；首发种类 9 道，非首发 15 道；覆盖 12 个轮次、10 名玩家、14 种动作。

子集偏向大事件轮次（R1、星门、IPO、BIS 规则、黄仁勋辞职、SEC 调查）。分数可能比全 83 道偏高。下面“诚实说明”里写了这一点。

## 方法：预测纪律

每道题，Agent 先查事实，再推理，再猜。猜的时候只用这些：

1. 该玩家在轮次日期之前的历史（trace 前缀）和状态（血量、金币）。
2. 轮次日期之前的事实：新闻、财报、公开表态、规则变化。来源是网上搜索（15 次）和仓库里的 roundEvidence（31 轮）。
3. 本轮的标题事件，当作已知输入。意思是：已知发生了这件事，猜玩家怎么反应。不猜事件本身会不会发生。

不许用的东西：

- 这道题自己的动作文字和种类（答案）。只在打分时才看。
- 本轮的逐动作证据（roundEvidence 里按玩家分的证据）。那是答案。
- 轮次日期之后的事。
- 效用公式（predict.py）。一次也没调。

## 事实帮上忙了吗

帮上了，而且帮得最多的是事件驱动的题。

- 星门（S4 1-2）：星门 2025-01-21 宣布，英伟达和甲骨文是技术伙伴和建设方。Agent 猜对了 NVDA 和 ORCL 都是 stargate。公式猜不对，因为它只看数字。
- 模型发布（S4 4-1）：Claude 4（2025-05-22）和 Grok 4（2025-07-09）是公开事实。Agent 猜对了 ANTH 是 claude、MUSK 是 spacex_xai、ALI 是 tongyi。
- 融资（S4 5-1）：甲骨文 380 亿美元债务包（2025-10-23）和 xAI 两轮融资（2025-07-01、2025-10-08）是公开事实。Agent 猜对了 ORCL 和 MUSK 都是 financing。
- IPO（S5 2-1、5-1、6-2）：S-1（2026-10-26）和定价区间（2026-11-10）是公开事实。Agent 猜对了 ANTH 三次都是 anthropic_ipo。
- BIS 规则（S5 5-1）：规则 2026-11-16 发布，字节海外算力直接受影响。Agent 猜对了 BYTE 是 bis_rule。
- SEC 调查（S5 6-1）：WSJ 2026-11-17 已报道 SEC 在查英伟达。Agent 猜对了 NVDA 是 sec_probe。

没帮上的地方，就是两道错的题。两道错的都是同一个原因：事件还没公开。

1. S4 1-1 MSFT：Agent 猜 msft_invest，实际是 stargate。星门是 2025-01-21 宣布的，比这轮（2025-01-20）晚一天。2025-01-20 那天没人知道星门要宣布。Agent 猜不对，是对的——它不该知道。
2. S5 1-1 ANTH：Agent 猜 claude，实际是 anthropic_ipo。这轮的日期是 2026-01-01，但 IPO 承诺是 2026-10 的事（S-1 是 2026-10-26）。2026-01-01 那天没有 IPO 的公开信号。Agent 猜不对，是对的——它不该知道。

结论：Agent 能预测“对事件的反应”，不能预测事件本身。事件已知，反应能猜对；事件未知，猜不对。这是这条线的边界。

## 两个数据发现

1. 有些轮次的日期和事件真实日期对不上。
   - S5 1-1 的日期是 2026-01-01，但 ANTH 的 IPO 承诺是 2026-10 的事。这道题按轮次日期算，对 Agent 不公平（事件还没发生）。
   - S5 3-2 的日期是 2026-11-05，但 BIS 规则是 2026-11-16 才发布。这两道题（BYTE overseas_rental、ALI bis_rule）Agent 是按“海外租赁趋势 + Megaspeed 调查 + RASA”猜对的，不是按规则文本猜对的。规则文本那天还没公开。
   - 建议：以后跑全 83 道时，把轮次日期和事件真实日期分开记。事件真实日期在轮次日期之后的题，要单独标注（不公平题）。
2. MUSK 的历史没用，事实有用。
   - MUSK 在前缀里最常见的种类是 musk_table（6 次），但这个种类在 83 道考题里一次也没出现。所以只看 MUSK 历史，永远猜不对。
   - MUSK 的三道题（spacex_xai、financing、financing）全是靠事实猜对的（Grok 4、两轮融资）。

## 诚实说明（这三点必须一起读）

1. 子集只有 24 道，不是全 83 道。子集偏向大事件轮次（事实最丰富的题），分数可能比全 83 道偏高。22/24 不能直接说成“Agent 在 83 道题上是 91.7%”。全 83 道的分数要跑完才知道（计划见下）。
2. Agent 本人知道 2025–2026 年发生了什么。推理可能受已知结果影响。我用的约束是：只列轮次日期之前的事实，写出推理过程，每道题的事实和理由都记在 predictions.json 里，别人可以逐条检查。但这个约束不能完全排除“事后诸葛亮”。分数要当作上限来读，不是最保守的估计。
3. Agent 拿到了标题事件当输入（“已知事件，猜反应”），公式没有这个输入。所以 22/24 对 1/83 的差距，一部分来自输入更好（事实 + 事件），不只是推理更好。这正是要测的东西（果实 6：先查资料再推理），但比较时要说清楚。

## 跑全 83 道的计划

事实库已经建好了（12 个轮次的标题事件 + 15 次网上搜索 + roundEvidence 31 轮）。剩下 59 道题主要是推理，不用再大面积查新事实。

步骤：

1. 按轮次分批做（剩下 59 道分布在同一个 12 个轮次里）。
2. 每道题写事实（带日期和来源）、推理、猜的种类、把握多大。记进 predictions.json。
3. 打分：全 83 道的总分，分首发 / 非首发，分把握，分事件给了 / 没给。
4. 跟公式（1/83）和分玩家规则（23/83）比。同一批题上，也跟玩家历史规则比。
5. 把轮次日期和事件真实日期分开记。事件真实日期在轮次日期之后的题，单独标注（不公平题），分数分开报。

## 下一步

1. 跑全 83 道（按上面计划）。
2. 把“查事实”做成可重复的步骤，不要只靠人脑推理：给每道题自动列出轮次日期之前的事实（从 roundEvidence 和搜索结果里取），再让 Agent 推理。这样以后新轮次来了也能跑。
3. 如果全 83 道的分数还明显高于公式和分玩家规则，就把“先查事实再推理”做成正式的预测方法，和 Agent 原型、神经网络、转移概率模型那几条线一起比，挑最好的组合。
