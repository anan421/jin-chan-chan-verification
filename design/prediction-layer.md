## 二、博弈论玩家模型

### 玩家与收益函数

18 名正式席，每名玩家一个收益函数。函数形式全席共享，参数按玩家类型分档。类型分五档：芯片供应商、云超大规模、模型实验室、杠杆基建、中国厂商。每档的参数不同，但函数结构相同。

收益函数写成：

`u_i(s, a_i, a_-i) = w_hp · ΔHP_i + w_gold · Δgold_i − c_lever · 杠杆惩罚 − c_rule · 合规成本 + w_pos · 位置项`

- ΔHP 与 Δgold：动作的血量与金币变化。取自 `Move` 的 `hpDelta` 与 `goldDelta`。`DState` 与 `Move` 能决定的量只有这些。
- 杠杆惩罚：金币为负且动作标了负债时计入。`liability` 标志已在 `Dynamics.lean` 里。
- 合规成本：动作种类在当前规则版本下被禁（`bannedKinds`）时，动作非法，不进收益计算，直接排除。规则版本是动作的参数。合法但昂贵的动作（例如许可申请成本）可设成本项，须引证据或标假设。
- 位置项：玩家在排名中的位置变化。排名由程序从增量算出（页面修复后）。位置项由同一批增量导出，不引入新数据。
- 人口与持卡不在收益函数里：`Move` 不带人口或卡获得输入，`DState` 不含人口与持卡。人口与持卡留在有限层（C6）与逐轮记录字段里。预测层在 Lean 一侧能用的量，恰是 `Move` 能决定的量。Python 一侧的收益模型可以用记录字段（人口、持卡）做辅助项，但这些项进不了 `Prediction.lean` 的定理。两层不要混。

### 收益参数：证据或假设，二选一

每个参数必须引证据，或明确标为假设。没有第三种状态。

- 引证据：参数值来自 trace（血量/金币序列）、`facts/ipo`、`facts/nvda`、政治记录文号、EDGAR 文号。证据指针写进收益模型文件。
- 标假设：没有证据的参数写成“假设”，带编号（例如 A1、A2），写进定理前提与合并报告的假设章。假设不得冒充已验证事实。假设变了，定理的前提变了，结论的适用范围也变了。
- 占位值：回测之前允许用占位参数跑通管线，但占位参数必须标“占位”，不得出现在任何“已验证”或“已校准”的表述里。

### 解概念

推荐：马尔可夫完美均衡（MPE）。

- 策略只依赖当前状态：`σ_i : DState → Move`。这与 `Dynamics.lean` 的状态机直接对接：状态是 `DState`，动作是 `Move`，规则版本是步的参数。
- 子博弈完美均衡（SPE）是参照概念，不用作计算口径：18 名玩家、同时行动、不完全信息，SPE 求解不可行。写进设计稿只为说明“我们没有假装算了 SPE”。
- 计算用最好回应动态：从当前状态出发，各玩家轮流对其他玩家预测动作做最好回应，迭代到不动点或循环。收敛到不动点，输出该均衡；收敛到循环，循环本身就是结论（例如杠杆循环：借钱、扩建、增收、再借钱）。
- 同时行动：每轮 18 名玩家同时出牌。最好回应针对的是其他玩家“预测的”动作，不是已观测的动作。迭代在预测空间里进行，不在真实时间里进行。
- 混合策略在 Python 一侧算（动作上的概率分布）。Lean 一侧只证纯策略的性质；混合策略的定理写成“支撑集内的每个动作都合法且保持不变量”。

### 输出：分布，不是单点

给定状态，预测输出是每名玩家的动作分布：动作种类上的概率分布，或下一符号单元上的概率分布。Headline 是众数动作加前 k 名的概率质量。单一确定动作不是预测输出。预测输出是分布/区域（高概率），不是“将会走这一步”。

## 三、符号动力

### 符号分区

`DState` 的状态空间是无限的（Int 字段）。按谓词分区，得到有限字母表。分区用页面已有的段位映射，不另发明：

- 血量段：王者（≥90）、宗师（80–89）、钻石（70–79）、铂金（60–69）、黄金（50–59）、白银（40–49）、青铜（30–39）、黑铁（<30）。
- 金币符号：正、零、负（负当且仅当负债）。
- 出局：活、死。
- 规则版本：当前生效版本。

一个符号单元 = 血量段 × 金币符号 × 出局 × 规则版本。单元数有限，转移图可算。

### 转移图与吸引子

- 节点是符号单元。边 A → B 当且仅当存在合法动作把 A 中的某个具体状态带到 B 中的具体状态。边由 Python 算出：对每个动作种类，解“存在 A 中具体状态，其像在 B 中”的约束（采样代表状态加区间推理）；Lean 一侧写成存在性命题。
- 可达序列是图上的路径。回归态是强连通分支（SCC）。吸引子是只出向自身的 SCC（汇 SCC）：进入后不再离开。例如杠杆循环（借钱、扩建、增收、再借钱的闭环）、去杠杆吸引子（降杠杆、现金流回正、不再借钱的闭集）。
- 规则变化是剪边：新规则版本禁掉动作种类（`bannedKinds`）或改血量上下界（`hpFloor`/`hpCap`），图上就是删边、重定节点边界。反身性循环写成：观察局面 → 写规则 → 剪边 → 玩家改道 → 新局面 → 再观察。这与设计稿 B 层是同一条循环，预测层把它算出来，验证层把它证出来。

### Lean 能证什么，不能证什么

能证：

- 不变集：符号单元集合在转移下封闭（从集合出发的边不离开集合）。证明用归纳，与 `invariant_run` 同一形状。
- k 步进入：从给定单元出发，k 步内进入集合 S。k 是显式数字，证明是 k 步归纳（或有界展开的可判定检查）。
- 可达集：`Reachable` 已在 `Dynamics.lean` 里。符号版是它的可判定抽象。

不能证：

- 现实未来。图上的路径是“可能”的轨迹，不是“将会”的轨迹。
- 现实进入哪个吸引子。吸引子是模型内的结论，不是现实的预言。
- 政治下一步写什么规则。规则更新永远是输入。

抽象合理性方向要写清：符号图必须过近似具体转移（每个具体合法动作都对应一条图边；图可以有多余边）。于是 Lean 的结论方向是：图上“从 A 到不了 B”推出“具体轨迹从 A 到不了 B”。反方向不成立：图上有路，不代表具体轨迹一定走那条路。

## 四、Agent 作为玩家

### 机制

每名玩家（或每类玩家）由一个 agent 实例扮演。输入：每名玩家的当前 `DState`、当前规则版本、历史（trace）、预测层输出（最好回应分布加吸引子信息）。输出：一个 `Move`，以 AgentClaim（kind=`propose_action`）发出。

### 过 gate：补一个接口缺口

今天的 `gate.py` 对 `propose_action` 只查 R2（证据与 subject 解析）与 R3（谓词可判定），不对其谓词求值（未来状态不在当前 trace 里）。但 R2 要求 subject 在当前 trace 里解析，未来轮次的位置解析不到，直接拒绝。所以预测动作今天过不了 gate。补法（三件，缺一不可）：

1. Schema v2：AgentClaim 加可选字段 `move`（一个 `Move`：player、date、season、actionKind、hpDelta、goldDelta、liability、rulesVersion）。不改 kind 枚举。
2. `gate.py` R2 扩展：未来 subject 形式（赛季 = 当前最大赛季 + 1，且玩家存在）解析为“未来位置”，不拒绝；其证据仍须解析（R2 不变）。
3. 预测步“先应用、再重验”：预测运行器把提议的 `Move` 用 `Dynamics.applyMove` 的 Python 镜像作用于当前状态。返回 none（非法动作）时 claim 拒绝，记为“被转移关系反驳”，留记录。返回新状态时，对扩展后的 trace 跑 C1–C12 与 Lean 构建，通过才记为 verified。谓词求值对象是候选状态，不是当前 trace。

### Agent 行为本身进检测

- 每次 agent 输出记一条日志：输入（当前状态、规则版本、预测输出）、输出的 Claim、gate verdict、重验结果。日志本身进 trace，带 `agent_id`。
- 协议检查（待建的 `agent_claims.py`）适用：覆盖率（每个新事件都被分类）、引用（每个 claim 都有来源）、可复现（确定性分类器跑两次，一次原序一次打乱顺序，结果一致）。
- 有争议的动作标 contested，阻塞整轮：两个 agent 对同一玩家同一赛季提议冲突动作时，R4 标 contested，整轮失败，直到其中一条被证据推翻（refuted）或修正。
- Agent 策略本身不是 Lean 函数（LLM agent 的策略写不成 Lean 定义）。Lean 能证的是“给定策略 σ，性质 P 成立”。对 LLM agent，检查是逐输出的：每个提议动作由 `applyMove` 验。确定性 Python 策略可以镜像进 Lean，证其性质。两条路都写清，不混。

## 五、回测（校准）

### 方法

把 agent 玩家在 2022–2026 已记录历史上重跑。每轮边界处，只给 agent 该轮之前的 trace 前缀（不给未来信息），让它提议下一轮动作，与 558 条真实动作对比。未来信息泄露是回测的第一号错误：前缀之外的数据一律不进输入。

### 命中率指标

- M1 动作种类全等：提议 actionKind 等于记录 actionKind（每玩家每轮）。
- M2 Δ血方向：sign（提议 ΔHP）等于 sign（记录 ΔHP）。
- M3 Δ金方向：sign（提议 Δgold）等于 sign（记录 Δgold）。
- M4 段位段全等：预测的下一血量段等于记录的下一血量段。
- M5 量级：|提议 ΔHP − 记录 ΔHP| 在容差内（容差由 Gu 定，例如 ±5 或 ±10）。
- 汇总：每玩家、每赛季、全体各一张表。不是一个数字。随机基线同表并列：动作种类随机选（基线 1/动作种类数），方向随机选（基线 50%）。命中率必须超过基线一个裕度（Gu 定）才算信号。

### Walk-forward 协议

防过拟合：参数拟合只用测试窗口之前的数据。推荐切法：S1–S3 拟合，S4–S5 测试；然后滚动。整段 558 条一次拟合、一次测试的回测不算校准，算拟合优度。

### 命中率低是机制错

命中率低，改收益模型，不改数据。这是 `classify.py` 已有的数据错与机制错之分在预测层的应用。机制错的反馈回路：改收益模型文件，版本号加一，全部回测重跑。改数据掩盖模型错误，是造假。

### 证伪条件

- M1 全体命中率低于随机基线：收益模型作废，重写。
- 某类玩家在三个赛季里 M2 方向命中率低于 50%：该类收益函数作废。
- 回测命中率随时间单调下降：规则变化未进模型，模型须加入规则版本项。
- Agent 系统性提议非法动作（`applyMove` 返回 none 的比例超过阈值，阈值由 Gu 定）：agent 的动作空间定义有问题。
- 预测分布长期把高概率放在事后未发生的动作上：校准失败，分布须重标定，不是调一个数字。

## 六、接口：怎么接现有层

### Dynamics.lean

策略是 `DState` 上的函数。新文件 `lean/Verification/Prediction.lean`（或 `Game.lean`）：定义 `Strategy := DState → Move`（单步策略；多步对局由 `run` 折叠），定义最好回应，定理形式是条件式：“如果全体玩家走 σ，则轨迹留在集合 S / k 步内进入吸引子 A”。定理的证明用 `invariant_run` 同一形状的归纳。Lean 证的是“给定 σ 的性质”，σ 本身来自博弈模型加回测。

### gate.py

`propose_action` 已有。须改三处（见第四节）：schema v2 加可选 `move` 字段；R2 扩展未来 subject；预测运行器做“先应用、再重验”。`gate.py` 本身不求值 `propose_action` 的谓词，不变。

### run.sh

预测步骤放在历史层之后：gate（已有 claims）→ 快速检查器 → 生成 `Trace.lean` → Lean 构建 → 预测（新步骤）→ 合并报告。顺序的理由：历史层没通过，不预测。不能从未经验证的现在出发推未来。预测失败不推翻历史层：历史层仍是 pass，预测章单独记 fail。合并报告加预测章（预测分布、命中率、假设清单），预测结果不进“已验证”标签。预测章与验证章分开写，不混。

### 需要的新文件

- `rules/payoff-model.json`（或 `models/payoff-v1.json`）：每名玩家（或每类玩家）的收益函数与参数。每个参数带证据指针或“假设”标签。版本号加一时全部回测重跑。
- `lean/Verification/Prediction.lean`：策略类型、最好回应、条件式定理（不变集、k 步进入）。
- `predict.py`：预测运行器。读 trace 加收益模型，跑最好回应动态与 agent 玩家，输出预测动作与分布，作用于分叉 trace，重验 C1–C12 与 Lean。
- `backtest.py`：2022–2026 重跑，算 M1–M5，walk-forward，随机基线并列。
- `symbolic.py`（或并入 `predict.py`）：符号分区、转移图、SCC/吸引子计算。
- `agent_claims.py`：协议检查（覆盖率、引用、可复现）。`STATUS.md` 已列为待建，预测层复用它，不另起一套。
- `daily_run.sh`：每日循环里预测跑在验证通过之后。`STATUS.md` 已列为待建。

### 预测输出的形状

每名玩家一个动作分布（动作种类上的概率，或下一符号单元上的概率）。Headline 是众数动作加前 k 名的概率质量。输出文件带三样东西：分布、命中率（回测）、假设清单。缺任何一样，输出不完整。

## 七、诚实边界

- Lean 证的是“如果策略是 σ，则性质 P 成立”。“玩家会走 σ”是博弈论加回测支持的模型主张，不是 Lean 定理。
- 高概率由两部分量化：模型稳健性（多少参数扰动与初值导向同一吸引子，即吸引域大小）与回测命中率（M1–M5，walk-forward）。
- Lean 不能证：现实未来；玩家会遵循收益函数；政治会写某条规则；现实中没有秘密协调。
- 预测失败不推翻验证层：过去的检查仍成立。预测失败推翻的是收益模型（机制错），触发模型修订。
- 预测是分布，不是 verdict。页面如果展示预测，必须同时展示分布、命中率与假设清单。只展示众数动作，是误导。
