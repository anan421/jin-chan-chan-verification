日期：2026-11-22。分支：`loop/round2-composite`（基于 main d044512）。代码：`composite.py`。结果：`runs/composite-round2-2026-11-22/results.json`。不改 live 模型，不合进 main。

组合没有打败 Agent 单独。

| 做法 | 猜对 |

| Agent 单独（普通 Agent） | **30/83（36.1%）** |
| 组合（保守规则） | 30/83（36.1%，打平） |
| 组合（主规则） | 28/83（33.7%） |

| 随机猜 | 约 4/83 |

## 这是什么组合

转移模型给基础概率（从历史来），Agent 读事实再调整。

- 转移模型：经典概率模型。学 P（下一个动作种类 | 玩家，上一个动作种类）。它不算分，直接数过去出现过多少次。分层回退 + 加 1 平滑 + 插值。它是只看历史里最好的（27/83）。
- Agent：读前缀（玩家状态、历史、规则、对手上一轮的动作、之前两轮的事实），推理后猜。它是全 83 道里最好的（30/83）。
- 组合：用一条决策规则把两者合起来。不是乘法（见下）。

## 第一性原理：玩家下一步由什么决定

从三份第 1 轮报告和数据里拆出来，玩家下一步由四样东西决定：

1. **习惯和连续性。** 玩家重复上次做的事，或重复自己最常做的事。转移模型抓这个（L1 玩家 + 上一个种类）。Agent 也用习惯。
2. **正在进行的线索。** 玩家在跟进自己刚开始的事（递了 S-1 就上市、产品线就出下一个产品）。Agent 跟线索，转移模型靠重复部分抓到。
3. **外面来的事件。** 新模型发布、规则变化、财报、调查。玩家对事件做反应。只看历史的模型看不到这个（24 条首发种类就是这么来的）。只有读事实的 Agent 能抓。
4. **玩家自己宣布的计划。** 他说了要做 X，就做 X。Agent 读事实能抓，历史看不到。

不合理的东西，要剔掉：

- **公式的假设（涨血涨金最多就选它）。** 已证伪（1/83；消融证明血量金币没有信号）。
- **乘法合并。** 第 7、10 轮已证明乘法压掉先验（打分拉得开，先验拉不开，打分赢了）。这里 Agent 根本不输出概率分布，乘法连定义都没有。所以组合必须用决策规则，不是乘法。
- **把两个预测当成一样可靠。** 它们各有各强的场合。转移模型强在重复和习惯（马斯克融资接融资、Anthropic 上市接上市）。Agent 强在事实和线索（能源轮、大事件）。合的时候要按场合分，不是按固定权重。

## 组合方法：决策规则（打分前就定好）

两条规则，都是打分前就定好的。没有在考题上调任何阈值。

**主规则（R-primary）：**

1. Agent 猜的种类从来没在历史里出现过（首发种类，转移模型零计数、看不到）：用 Agent 的。事实指向历史看不到的东西，Agent 说了算。
2. 否则，Agent 猜的种类在转移模型的前三名里：用 Agent 的。Agent 在历史觉得可能的几个里挑一个。
3. 否则：用转移模型的第一名。Agent 的猜既不是首发、又不在历史前三名，默认用历史。

**保守规则（R-conservative，只做对照）：**

1. Agent 猜的种类从来没在历史里出现过：用 Agent 的。
2. 否则：用转移模型的第一名。

“从来没出现过”是用 trace 算的：Agent 猜的种类在该轮之前的所有轮次里一次也没出现过。这个信号不看答案，只看前缀。

**输的地方（主规则比 Agent 少 2 道）：**

主规则在 5 道题上把 Agent 的猜换成了转移模型的第一名，结果 5 道全错，Agent 本来对 2 道：

- S5 2-1 ANTH：实际是 anthropic_ipo。Agent 猜 anthropic_ipo（对），转移模型猜 claude（错）。主规则换了转移模型，丢 1 道。
- 另外 3 道（S4 1-2 TSMC、S5 4-1 NVDA、S5 6-1 NVDA）：两边都错，换不换都一样。

**主规则在“前三名里用 Agent”这个分支上丢了 6 道：**

转移模型独对的 6 道，全是 Agent 猜在转移模型前三名里、但没猜第一名，主规则用了 Agent，结果错了：

- 6 道全是 Agent 想多了、偏离了习惯：MUSK 两次融资猜成 spacex_xai、ANTH 两次上市猜成 claude、ORCL 两次融资猜成 stargate。转移模型（重复上一个动作）全对。

**Agent 独对的 9 道，主规则抓住了 7 道，丢了 2 道：**

- 抓住的 7 道：3 道首发 energy（上面已说）+ 4 道“前三名里用 Agent”（S4 1-2 MUSK 的 colossus、S4 5-1 ORCL 的 financing、S5 4-1 ANTH 的 anthropic_ipo、S5 5-1 ORCL 的 financing）。
- 丢的 2 道：就是上面“默认用转移模型”丢的那 2 道（S4 1-2 MSFT 的 stargate、S5 2-1 ANTH 的 anthropic_ipo）。Agent 的猜不在转移模型前三名里，主规则默认用了转移模型，错了。

## 为什么没打败 Agent

四条原因，都是数据里看得见的：

1. **两边重合太多。** Agent 和转移模型 52/83 猜得一样。不同意的 31 道里，Agent 对 9 道，转移模型对 6 道，两边都错 16 道。组合能争的只有那 31 道里的 15 道（9 + 6），空间本来就不大。

2. **“前三名”这个过滤器太松。** Agent 的猜在转移模型前三名里的有 75/83 次（90%）。所以“在前三名里用 Agent”几乎总是触发，等于直接用 Agent。过滤器没有起到筛选作用。原因是转移模型的概率分布很平：第一名概率中位数只有 0.112，最高才 0.285，58/83 的第一名概率不到 0.15。它从来没有把握，前三名覆盖的面很广。

3. **“默认用转移模型”这个分支是错的。** 5 次默认，全错（0/5）。Agent 的猜不在前三名里时，转移模型的第一名也全错。这 5 道里 Agent 还对了 2 道。所以默认用转移模型是帮倒忙。Agent 的猜不在前三名里，往往说明 Agent 在猜一个历史看不到的东西（事件驱动），这时候 Agent 是对的，转移模型是错的。

4. **Agent 的把握是反的，没法用来路由。** Agent 独对的 9 道里，把握 low 的有 6 道、medium 3 道、high 0 道。Agent 在它真正有独到见解（和历史唱反调）的时候最没把握。转移模型独对的 6 道里，Agent 的把握有 high 1 道、medium 3 道、low 2 道。Agent 在它想多了的时候反而比较有把握。所以把握分不清“真见解”和“想多了”，不能用来决定听谁的。

还有一条：**Agent 很少猜全新的种类。** 83 道里，Agent 只猜了 3 次从来没出现过的种类（全是 energy，全对）。24 条首发种类里，Agent 只尝试了 3 次。所以“首发种类用 Agent”这个机制虽然全对（3/3），但触发太少，贡献只有 3 道。Agent 默认猜的是出现过的种类。

保守规则打平（30/83）的原因：它在能猜的 59 条上用转移模型（27 道，和 Agent 在这 59 条上的 27 道一样多，只是猜对的题目不完全一样），在首发的 24 条上用 Agent（3 道）。总数和 Agent 单独一样，只是换了个组合方式。没有更好，只是相等。

## 先查资料那条线的子集分析（24 道）

先查资料的 Agent（search-first）在 24 道子集上 22/24（91.7%）。同一批 24 道题上：

| 做法 | 24 道子集 |
|---|---|
| 先查资料的 Agent | 22/24 |
| 普通 Agent | 7/24 |
| 转移模型 | 6/24 |
| 组合（转移 + 先查资料，主规则逻辑） | 14/24 |

注意：24 道子集偏向大事件轮次（事实最丰富的题），不是全 83 道的代表。22/24 不能直接说成全 83 道的分数。

但这个子集说明了一件事：**主规则的“默认用转移模型”分支，对先查资料的 Agent 伤害更大。** 组合（转移 + 先查资料）只有 14/24，比先查资料单独（22/24）少 8 道。丢的 8 道全是“默认用转移模型”：先查资料猜对了（stargate、capex、spacex_xai、financing、anthropic_ipo、bis_rule），转移模型猜错了，主规则换了转移模型，全丢。先查资料的猜不在转移模型前三名里时，往往是它靠事实猜对了事件驱动的动作，转移模型看不到。

结论：**事实才是大头，不是组合。** 先查资料（真去查新闻、财报、规则）在大事件题上 22/24，普通 Agent 只有 7/24。差 15 道。组合（转移 + Agent）最多争 6–8 道（完美路由的上限 36 对 Agent 的 30）。事实的增量比组合的增量大得多。

## 诚实说明

- 两条规则都是打分前就定好的，没有在考题上调阈值。主规则没有打败 Agent，是诚实的结果，不是调参失败。
- 前缀的计算和转移模型的“首发”标志逐项对上了（0 处不符）。转移模型 27/83 和 Agent 30/83 都复现了（和各线自己报的数一致）。
- 83 道题太少。28 对 30 差 2 道，分不出是真差还是运气。但主规则的“默认用转移模型”分支 0/5、全错，是结构性的问题（见上），不是运气。
- 组合用的 Agent 是普通 Agent（只读前缀 + 之前两轮的事实）。先查资料的 Agent 只跑了 24 道子集，没有全 83 道的数。24 道子集的比较是子集比较，不是全 83 道的比较。
- Agent 有泄漏风险（它从训练里知道 2025–2026 年的事）。普通 Agent 预测时只用前缀，先查资料的 Agent 只列轮次日期之前的事实。分数要当作上限来读。

## 下一步

按优先级：

1. **等先查资料跑全 83 道。** 那条线（loop/round2-search-first-full83）正在跑。先查资料在 24 道子集上 22/24，全 83 道的分数是关键。如果全 83 道也明显高于 30/83，事实就是下一轮的主方向。
2. **组合的默认方向要反过来。** 主规则错在“默认用转移模型”。下一轮的组合应该默认用事实 Agent（先查资料），只在 Agent 没有事实信号的时候才用转移模型。比如：Agent 引用了具体 dated 事实就听 Agent 的；Agent 没引用事实、纯靠习惯猜的时候，才听转移模型的。这需要先查资料的 Agent 输出里带“引用了哪些事实”（它已经带了 facts_used），下一轮可以直接用这个信号路由。
3. **转移模型当默认，只适合“正常”题。** 保守规则证明了：能猜的 59 条上转移模型和 Agent 一样好（27 道）。所以转移模型可以当“正常题”的默认，Agent（带事实）专门处理事件题和首发题。但这个分工要靠“这道题是不是事件题”来路由，不是靠前三名。
4. **不要再用“前三名”做过滤器。** 它太松（75/83），不起筛选作用。转移模型的概率分布太平均，第一名概率中位数 0.112，说明它从来没有把握。
5. **把握不能用来路由。** Agent 的把握是反的（独对时多半是 low，想多时反而有 high）。要修把握分级（按证据强度分），或者干脆不用把握路由。
