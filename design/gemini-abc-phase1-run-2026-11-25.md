## 1. 批的定义

- 一批 = 对 54 道题（Q001–Q054）按题号顺序完整过一遍，每题只看自己的材料包（见第 3 节），不看同批其他题的答案，不看上一批的预测文件。
- 每组跑 3 批：A 组 3 批（脚本，三批同一程序）、B 组 3 批、C 组 3 批（预测员本人，三遍独立过题，每遍重新读材料）。
- 批内顺序固定为 Q001→Q054。批间独立：做下一批时不重读上一批的预测文件；如需核对，只在全部 6 批人工批做完后核对。
- 预测员：B 组与 C 组为同一人（本任务执行员），同一套读材料、选类别的程序（第 5 节），只换材料，不换人、不换程序。

## 2. A 组（纯历史基线，脚本算）

- 对每题 Q：取同一玩家在干净集里 date 严格早于 Q.date 的题目类别，取众数。
- 平局处理（跑前写定）：先比票数；票数相同比该类别在全部 54 道题里的总数；仍相同按固定类别顺序取先者。固定顺序：`model_release, infra_capex, capital_deal, chip_supply, policy_regulatory, hold_defend`。
- 无历史时 fallback（跑前写定）：取全部 date 严格早于 Q.date 的干净集题目的类别众数（同样平局规则）。若早于 Q.date 的题目为 0 道（即 2025-01-01 的题），fallback 为 `model_release`（54 道里 model_release 与 infra_capex 并列最多 16 道，按固定顺序取先者）。
- A 组是确定性脚本，三批结果必然相同。噪声带 = A 组三批平均分的极差，预期为 0。采用门槛 = max(11, 本轮噪声带），预期为 11 道。此结论在跑后如实记录，不因噪声带为 0 而改口径。

## 4. 题面

- 题面不写答案。题面格式（每题相同）：“玩家：{player}；轮次：{round}；预测点：{date}。该玩家在预测点前（严格早于 {date}）的棋盘记录与（C 组）前瞻指引如下：……。请预测该玩家在本轮（{round}）的动作属于以下 6 类中的哪一类：model_release / infra_capex / capital_deal / chip_supply / policy_regulatory / hold_defend。只选一类。”
- hold_defend 的含义在题面里写明：“hold_defend = 该玩家本轮在棋盘内无重大公开动作记录”。
- 预测文件不写 evidence 原文（防事后核对时把答案写进预测文件）；只写 question_id、预测类别、规则标签（第 5 节）、一句话理由（理由只引用材料包里的事实，不引用本题 evidence）。

## 5. B/C 组选类程序（同一套，跑前写定）

按以下顺序逐条适用，先命中的为准：

- (a) 指引/计划直指：材料包里有具体计划或宣布，其时限覆盖预测窗口，且点名了具体的下一动作类型（例如多年期基建投资计划→infra_capex；点名的下一代模型→model_release；已披露条款的募资/IPO 进程→capital_deal），选该类型。通用表述（“资本开支将增长”“收入将增长”）不触发 (a)。
- (b) 近线延续：最近一到两条记录属同一类别且构成连续动作线（例如连续扩产、连续融资），选该延续类别。
- (c) 历史众数：取该玩家材料包里主动条目的类别倾向；无法从措辞定类别时退回 A 组众数（即该玩家干净集历史众数）。
- (d) 无历史：材料包为空（该玩家在预测点前无任何 audit 条目且无指引），选 model_release（与 A 组 fallback 一致）。
- hold 规则：只有同时满足以下两点才可选 hold_defend：(i) 该玩家在紧邻上一轮无任何 audit 条目；(ii) 材料包里无任何覆盖本预测窗口的前瞻计划或待办动作。任一不满足，不选 hold_defend，改按 (a)–(d) 选。
- 每题记录规则标签：`a` / `b` / `c` / `d` / `hold`，及一句话理由。

## 6. 打分与审计

### 6.1 打分

- 计分：预测类别与干净集 `category` 完全一致计 1 分，否则 0 分。`secondary_label` 不参与计分。
- 两套独立打分脚本，结果须完全一致：`eval_runner.py`（主脚本，含 A 组计算与材料包生成）与 `score_check.py`（独立重写，只读干净集与预测文件，重新算分）。两脚本各输出每组每批分数、总准确率、6 类分项命中率；数字不一致即停表查原因，不出报告。
- 预测文件格式：每组每批一个 JSON 文件，`runs/gemini-abc-2026-11-25/{group}-batch{n}.json`，含 question_id、prediction、rule、reason。

### 6.2 McNemar 与汇总口径（跑前写定）

- 主口径：三批汇总（pooled）：162 个题目-批次对（3 批 × 54 题），B 组与 C 组配对。b = C 对 B 错的对数，c = B 对 C 错的对数；双侧精确二项检验（p = 2 × min(P(X ≤ min(b,c)), P(X ≥ max(b,c)))，X ~ Bin(b+c, 0.5)，纯标准库实现，不用 scipy）。
- 敏感性口径：每批单独 McNemar（54 对），三批各报 p 值。
- 噪声带：A 组三批平均分的极差（单位：道）。采用门槛 = max(11, 本轮噪声带），单位为道；增益 = C 组三批平均分 − B 组三批平均分（单位：道）。

### 6.3 协议第 6 节六条件（操作化，跑前写定）

1. 增益严格大于采用门槛（等于不算过）。
2. 主口径 McNemar 双侧 p < 0.05。
3. 增益 ≥ 3 道。
4. 增益来自 ≥ 2 道题：pooled 口径下，C 对 B 错的对子涉及的不同 question_id ≥ 2 个，且单个 question_id 占净增益对数（b − c）的比例 ≤ 50%。
5. 最弱一项不跌：C 组最弱种类命中率（6 类分项命中率的最小值，三批平均）不低于 B 组最弱种类命中率。报告里须写明：chip_supply 只有 3 道、policy_regulatory 只有 1 道，最弱项几乎必然是 0% 或 100%，条件五判定力弱；“最弱项平局”不作为通过的证据。
6. 增益不在泄漏题上：把敏感集 {Q012, Q021, Q025, Q040, Q054}（4 道已排除泄漏 + 1 道边界保留）从 54 道里拿掉，在剩余 49 道上重算增益与条件一至五；条件一至五在 49 道子集上仍全部满足，条件六才算通过。49 道子集上条件一的门槛仍用 max(11, 本轮噪声带）（绝对道数，不按比例缩）。

### 6.4 暂定 / 丢掉（协议第 6.2 节，操作化）

- 全部六条件满足 → 采用。
- 增益为正但未超门槛，且同时满足以下两点 → 暂定：(i) 真新信息：≥ 2 道题满足“B 组三批全错且 C 组三批全对”；(ii) 无系统性帮倒忙：没有任何一类满足 C 组三批平均命中题数比 B 组低 ≥ 2 道。
- 其余情形（增益为 0 或负；增益只来自泄漏题；有系统性帮倒忙；无真新信息）→ 丢掉。

### 6.5 审计（跑后，脚本 + 人工）

- 日期审计：材料包里每条事实的 date 严格早于本题预测点；等于或晚于预测点的为 0 条。脚本逐条核，输出违规数。
- 题面审计：题面不写答案；预测文件不含 evidence 原文。
- 泄漏复核：跑后 grep 全部材料包，确认不含“2200”；确认 4 条已排除指引不在对应题的 C 组材料包里；确认 S5-R11-036 不在 Q054 的任何材料包里。
- 审计记录写进 `runs/gemini-abc-2026-11-25/audit.json`。

## 9.1 规则 (a) 解释口径（C 组第 1 批开始前写定，统一用于全部三批 C 组，不改规则只作解释）

- (a) 触发须同时满足：指引条目点名了具体的下一动作类型，且其时限覆盖预测点。
- 时限判定：有明确年限/产能目标的多年期计划，用其 stated horizon（如 3800 亿元三年计划、Stargate 四年计划、“2026 年内上线”）；无明确结束日的进行中计划（如 Colossus 扩容），只在宣布日起 12 个月内算覆盖预测点，超 12 个月算过期；已发生的发布/财报数字（“已发布”“Q3 数字”）不指向下一动作，不触发 (a)；“将很快到来”且所指事件已在预测点前发生（如 2026-07-31 的 V4-Pro GA 预告对 2026-11-01 的题），不触发 (a)。
