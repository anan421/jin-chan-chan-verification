# 第 3 轮：主题轮分人（theme → roles → person）

## 目标

在先查资料 Agent（60/83，全 83 道最好成绩）的基础上，修它最大的错题类别：
主题轮里人分错了。先查资料错的 23 道里，最大的一类是主题猜对了、动作安到了
错误的人身上（星门轮 S4 1-2 错 4 道；S5 3-2 HUAWEI 和 TSMC 互换 2 道）。

## 方法

每一轮做三步，全部显式写出来：

1. **判主题**：从轮次日期之前的事实判这轮的主题（大事件/主线是什么）。
2. **分共享还是分化**：共享主题轮是标题事件以同样方式打到整个大厅
   （多数人做同一种动作）；分化轮是各玩家在主题里扮演不同角色。
   多数轮是分化轮。
3. **按角色猜**：列出主题里涉及哪些玩家、每个人扮演什么角色
   （建园区、供芯片、融资、是客户、竞争对手在反应、不受影响），
   按角色 + 各自习惯 + 各自宣布的计划猜每个玩家的动作，
   不要只按主题猜。

补充：
- 没有角色的玩家按习惯（最常做的种类）或正在进行的线索猜。
- 考虑“无聊”答案 capex（资本开支是真实常见的动作）。
- 考虑“别人的事件”（有些轮次整个大厅的动作记在另一个玩家的事件种类下）。

## 输入（和先查资料同一套，保证可比）

- 题目：83 道（S4–S5 可分类记录），每轮一个题目文件（不含答案）。
- 事实：facts-roundEvidence.json（31 轮证据）+ 网上搜索，只用轮次日期
  当天或之前的事实。
- 标题事件：已知输入（和先查资料一样）。玩家本人是事件主角时不给；
  事件真实日期在轮次日期之后的也不给（S5 1-1 的 IPO、S5 6-2 无单一事件、
  S4 5-1 无单一硬指针）。
- 不用乘法合分数。不用效用公式。

## 单轮隔离

13 个轮次预测员，每人只看自己那一轮的题目文件 + 事实库。
不读 test83.json、trace-latest.json、predictions-full83.json、
scored-full83.json、data.json、其他轮次的文件。
（第 2 轮两条线都出过漏题：一次给多轮题目会让预测员看到前面轮次的答案。）

## 题目文件

`runs/theme-person-round3-2026-11-22/context-S<season>-<label>.json`（13 个文件，
83 道）。用 `build_contexts.py` 从 trace-latest.json 生成（按赛季、轮次、玩家
连接——test83 的 idx 是旧 trace 位置，39/83 对不上新 trace）。
验证：复现先查资料现有的 59 个题目文件条目，0 处不符。
字段：q_idx、trace_idx、season、round_label、round、date、player、
hp_start、gold_start、rules_version、first_appearance、
player_history_counts、player_most_frequent、player_last_kind、
player_last3（该玩家在之前 3 轮里的动作种类）、prev_round_kinds。

## 打分

`score.py`：按 q_idx 连接答案，用脚本打分。输出总分、分轮、分玩家、
首发/重复、把握分级、和先查资料的配对比较（都对 / 只主题轮分人对 /
只先查资料对 / 都错）、目标组（S4 1-2、S5 3-2）逐题对照。
