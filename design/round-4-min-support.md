# 第 4 轮：期望增量加最小支持数与收缩（审计改法 4，P1）

## 问题（plain 语言）

v3 这个动作在全部 558 条记录里只出现过 2 次，平均一次涨 7 点血——是全场最高的单次涨幅。
旧模型直接拿这 2 次的平均值当期望，于是几乎每个玩家都被预测去做 v3：
测试窗 234 次预测里 v3 占 174 次（74.4%），实时预测 18 名玩家里 13 名是 v3。
但 v3 在测试窗里实际一次也没出现。2 条数据决定了 174 次预测。

## 改法

n < 5 的种类不用它的历史均值，改用收缩公式向全局均值收缩：

    期望增量 = (n × 种类均值 + k × 全局均值) / (n + k)，k = 5

n 的口径：在预测时刻可用的前缀历史里，该种类的实例数。
实时预测用全部历史；回测里每一轮只用该轮之前的前缀，不用未来数据。

分层（由细到粗，上一层样本不够就向下一层收缩）：

1. （玩家，种类）：n >= 5 用原始均值；n < 5 向种类均值收缩。
2. 种类（全席）：n >= 5 用原始均值；n < 5 向全局均值收缩。
3. 全局均值：全部前缀动作的平均增量。

种类一次也没出现过（n = 0）时，公式退化为全局均值本身——回退，不是零。

例子（S1–S3 前缀，全局均值 dHP +0.41、dgold +1.05）：
v3 n = 2、原始均值 (+7.00, +2.50)，收缩后 (+2.30, +1.47)，不再是全场最高。
llama n = 5，正好达标，用原始均值 (+3.20, +1.80)。

## 决定：收缩，不排除

审计给了两个选项：收缩，或把薄种类直接排除出候选集。选收缩。
排除是用法令删证据：薄种类里仍有真实信息（v3 两次确实都涨血），删掉等于
假装它不存在，还会人为缩小候选集。收缩按证据多少给权重：证据越少，
期望越靠近全局均值；薄种类想被选中，还得靠排位项赢回来。证据到了 n >= 5，
自动恢复原始均值，不用再改代码。

## 血量段与规则版本分组：本轮没做，原因有数

审计原文还提到按玩家、血量段、规则版本分组算均值。实测了 S1–S3 前缀
（324 条）的单元格样本量：

- （玩家，血量段，规则版本，种类）：94 个格，0 个达到 n >= 5，最大 n = 4。
- （玩家，血量段，种类）：69 个格，6 个达到 n >= 5。
- （玩家，规则版本，种类）：91 个格，2 个达到 n >= 5。
- （玩家，种类）：54 个已知种类格，8 个达到 n >= 5。

四维分组在现有数据上永远达不到门槛：它永远用不上原始均值，只会多一层
收缩噪音。所以本轮只做到（玩家，种类）→ 种类 → 全局三层。
血量段与规则版本分组不是不要了，是数据撑不起，等 trace 变长或改成分层
模型时再做。这是一个待办，不是遗漏。

## 还差什么

- 猜中次数仍是 1/83：收缩只去掉了 v3 的虚假优势，没让模型猜中动作。
- 实时预测仍集中：claude 12/18（66.7%），高于 50%。但机制变了：
  claude 是支撑充分的种类（n=5，用原始均值），不是小样本问题；
  进一步去集中归第 5 轮可行表与第 6 轮 c_rule，不是本轮的错。
- 实时预测的最佳回应不再收敛：20 次迭代跑满，cycle=True；
  基线是 2 次迭代收敛。收缩压平了效用差距，玩家来回换动作。
  预测照常产出，重验证照常通过，但动态稳定性变差了——记为待办。
- M6 校准度 0.922，仍不通过：模型仍过度自信，只是比以前轻一点
  （顶桶 [0.99, 1.0] 已空，众数概率从 0.62–1.00 降到 0.30–0.60）。
- 血量段与规则版本分组未做（见上），等数据或模型改法。
- 全量（S1–S5，样本内）M2 从 41.48% 降到 37.59%——样本内数，
  不进验收门，只记一笔。
