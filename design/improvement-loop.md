# 预测层改进循环（Improvement Loop）

## 目标
让预测变好。目标是：模型猜中下一张牌的次数，稳定超过随机水平。达到目标，或连续 3 轮没有变好，就停，报结果。

## 做法：小步迭代（软件工程思想 + 大模型能力）
- 任务切小。每一轮只改一小处（一个改法，或一小批相关的改法）。
- 每一轮的步骤：
  1. 选改法：从审计清单里按优先级取（审计报告的改法清单是输入）。
  2. 改：只改该改法涉及的地方。
  3. 形式化检验：跑 ./run.sh，历史层必须全过。没过，退回，不进下一步。
  4. 测：用测试集（模型没见过的数据）量准确率，与改前对照。
  5. agent 审：审计员审这个改法（对不对、有没有漏）。
  6. 留或退：测试集上比改前好、且检验全过，才留；否则退回。
  7. 记录：STATUS.md 与设计稿更新。
- 每批 3 轮。跑完一批，报一次（plain 语言：变好多少、还差哪里、下批改什么）。然后开下一批。

## 采用规则（v3 的教训）
只有测试集（样本外）上比改前好，才采用。只在见过的数据上好，不算。

- 合并条件：形式化检验全过 + 测试集上比改前好。满足才合并到 main。不满足，分支废弃，不合并。
- PR：GitHub 接通后，每轮一个 PR，合并即一轮完成。本地先用分支 + 合并提交走同一流程。

plain 语言。短句，一句一个意思。只说这东西本身（预测准不准、哪里不对、改了什么、改完好多少）。不用内部词汇。
