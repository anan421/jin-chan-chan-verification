# 前沿 AI 实验室是怎么做实验的

## 问题

Anthropic、OpenAI、DeepMind 这些前沿实验室每天做很多实验。他们怎么做评估、怎么做消融/对照、怎么做迭代、怎么判一个做法好还是坏、怎么处理小测试集、怎么追踪结果、怎么并行跑多路？学他们的方法，用在我们的项目上。

我们的项目：金铲铲复盘里的预测模型（猜每个玩家下一步做什么）。现在的公式在 83 道考题上只对 1 道，简单规则（只看每个玩家自己的历史）对 23 道。我们正在 4 路并行试不同做法（Agent、神经网络、转移概率模型、先查资料的 Agent），每轮留最优者、继续跑。问题是：我们怎么做实验、怎么做评估、怎么做迭代，才更像前沿实验室的做法？

## 方法

按 BootLoops 全流程跑：定问题 → 三轮搜索（3 个侦察员并行：Anthropic、OpenAI/DeepMind、通用实验设计）→ VERIFY（主 agent 自己直读一手来源）→ VET 两轮（怀疑论复核员，第一轮 20 条断言 13 确认 7 纠正；第二轮只核 7 条已纠正的，6 确认，1 处再修正）→ 空地 → 果实。

一句话先说结论：**前沿实验室赢在实验的纪律，不在模型本身。**他们先写 eval、选和估分开、在同一批题上配对比较、先量噪声、按最弱一环打分、失败先分类、多路共享日志、一个结论三路印证、eval 是活的。我们这 8 件事一件都没做——这就是为什么 4 批公式小改全是死跑。

## 散点（已核验的事实）

### 评估驱动开发

1. **先写 eval 再开发。**Anthropic《Demystifying evals for AI agents》（2026-01-09）原话：“We recommend practicing eval-driven development: build evals to define planned capabilities before agents can fulfill them, then iterate until the agent performs well.”（先写 eval 定义计划中的能力，再迭代直到 agent 做好。）20–50 个取自真实失败的简单任务就是很好的起点；早期改动效应大，小样本就够。0% pass@100 最常是任务本身坏了，不是模型不行。评终态不评路径（订没订到票看数据库有没有 reservation，不看 agent 说了什么）。能力 eval 应从低通过率起步，饱和后“毕业”转回归套件。读 transcript 是必修课；“失败要显得公平”。
2. **Hillclimb 纪律。**Anthropic《Automating eval design and hillclimbing》（Lance Martin，2026-09-28）：每轮只改一处；train 涨、test 平就回退；开始前先验噪声（噪声须小于会采取行动的最小改进）；分数停滞 2–3 轮后停下来，把剩余失败按原因分类；增益在噪声内就说出来、建议不合并。客服 benchmark：44 张工单（30 张搜寻 + 14 张 held-out），最终配置在 held-out 14 张上 90.5%，对原始配置 78.6%，成本约五分之一。claude-api skill eval 从 66% 到约 88%（无 held-out 数）。
3. **只抓“改行为”走不出 demo。**Hamel Husain《Your AI Product Needs Evals》（2024-03-29）：做不好的共同根因是没有稳健的评估系统；改进速度取决于三件事——评估质量、调试（看日志/traces）、改行为；只抓第三件的人永远走不出 demo。三层评估：Level 1 单元测试、Level 2 模型与人工评估、Level 3 A/B 测试，成本 Level 3 > Level 2 > Level 1。Rechat 有数百个单元测试，按新失败持续更新。先记 traces，消除看数据的所有摩擦。
4. **先做错误分析，再写 eval。**Husain & Shankar《Field Guide》（Lenny's Newsletter）：不要从现成指标起手，先做错误分析；指定一名领域专家作质量仲裁者（“benevolent dictator”）；给约 100 条真实交互做开放编码，再轴向编码归纳为不超过 10 个主要失败模式，计数排序。LLM-as-judge 的 ground truth 切分为 train 10%–20%、dev 40%–45%、test 40%–45% 三份，judge 只在 dev 上迭代，test 集全程不动。二值标签，不用 1–5 量表（3 和 4 的区分主观且不一致）。

### 并行与迭代

5. **确定性指标 + 棘轮 + 150 路并行。**Anthropic 性能冲刺复盘（2026-09-23）：8 月两周，claude.ai 核心体验约 3 倍快（标题）；三项 p75 明细：新加载 3.1 秒→0.55 秒、新建 Claude Code 会话 0.8 秒→0.3 秒、加载 Cowork 云会话 2.6 秒→0.73 秒；覆盖 4 段旅程，占用户活动 95%；高峰时同时运行 150+ 线程；总计合并 3,000+ 改动，零面向客户的事故或回滚。方法核心：壁钟时间太抖，不能做 CI 门，改用确定性计数（Valgrind 下 `node --predictable` 的指令数、React commit 数、DOM 变更数）；每个新 benchmark 有两项工作——实验室里能推动的指标，和 CI 里只能单调下降的数字（棘轮）；先在两条热路径上把指令数压 48% 与 31%、壁钟降 78% 与 44%，证明计数跟踪壁钟后，才把两个新棘轮签入。中心教训原话：“With Claude, measuring something makes it tractable.”（能量化，Claude 就能优化。）
6. **多智能体赢在 token，不在架构。**Anthropic 多智能体研究系统（2025-06-13）：Opus 4 做 lead、Sonnet 4 做 subagent 的多智能体系统，在内部 research eval 上比单 agent Opus 4 高出 90.2%（相对提升，不是绝对分）。BrowseComp 上三个因素解释 95% 的性能方差，其中 token 用量单独解释 80%。agent 通常用约 4 倍于聊天的 token，多智能体约 15 倍。约 20 个真实查询起步；早期一个 prompt 改动可把成功率从 30% 提到 80%。注意：Anthropic 自己说多智能体奏效主因是花了更多 token，未做等 token 对照。
7. **并行 + 外层聚合 + 预先承诺评分标准。**Anthropic 自动审计 agent（2025-07-24）：工具型调查员 agent 在现实条件下解出审计游戏 13%，多个 agent 并行 + 外层聚合循环后提到 42%；评估构建 agent 区分“有植入行为 vs 无植入行为”的模型，88% 的 run 成功；广度优先红队 agent 发现 7/10 个植入测试行为。评分标准（根因正确性 + 列出 52 个偏差中的几个）在看最终结果前预先承诺。作者自己承认：同一审计游戏环境既当开发环境又当测试环境，存在 dev/test 污染。
8. **逐次减半 + 多 bracket。**Hyperband（arXiv:1603.06560）：把超参优化表述为纯探索、非随机无穷臂老虎机问题；Successive Halving：给 n 个配置均匀分配预算，评估后按淘汰因子 η 淘汰（η=3 时每轮留 1/3、淘汰 2/3），重复至剩 1 个；Hyperband 用多组 bracket 对冲“试多试少”的权衡，不用预先知道收敛速度。v4/JMLR 版摘要称比贝叶斯优化方法快“超一个数量级”；v1 摘要（2016）没有给数字，只说“在有利条件下有显著加速”。

### 消融与对照

9. **一个结论，三路不同方法各算一次。**Chinchilla（arXiv:2203.15556，2022-03-29）：用三路不同方法估计同一最优前沿，三路结论一致（指数 a=0.50/0.49/0.46，b=0.50/0.51/0.54，Table 2 带 bootstrap 的 10th/90th 百分位区间）。训了 400+ 个模型（70M–16B 参数）。Chinchilla 70B/1.4T token，MMLU 67.6%（5-shot），比 Gopher 高 7.6 个百分点。Kaplan 被纠正的原因：固定 token 数和固定学习率 schedule、且多数模型 <100M 参数。注意：论文内部 token 范围不一致（摘要 5–500B，正文 §3 称 5B 至 400B 以上）；摘要的 MMLU 67.5% 是四舍五入，正文是 67.6%。
10. **人评是主指标，公开数据集只作回归检查。**InstructGPT（arXiv:2203.02155，NeurIPS 2022）：三步——SFT、奖励模型、PPO；标注团队 40 名承包商；175B InstructGPT 被偏好胜过 175B GPT-3 的比例为 85±3%（95% 置信区间）；PPO 混入预训练分布对数似然项（PPO-ptx）大幅减少公开 NLP 数据集上的回归，且不损失标注员偏好分。两处口径纠正：21% vs 41% 是闭域任务幻觉率，不是 TruthfulQA（TruthfulQA 的结果是“真实且有信息量的回答约为 GPT-3 的两倍”）；毒性输出少约 25% 只在“提示要求礼貌/尊重”时成立，无此提示时改善消失。
11. **总分取最弱一环。**ML Test Score（Breck 等，NIPS 2016）：给生产级 ML 系统打分的 rubric，分 4 个部分，每部分 7 项；每项手动执行并记录得 1 分，有自动重复运行的系统再得 1 分；总分取 4 个部分分数的最小值；0 分 = 更像研究项目，7–10 分 = 强自动化测试与监控、适合关键任务，12+ 分 = 卓越。要拿简单模型当基线定期比；要在重要数据切片上测质量（别被全局均值掩盖）；离线代理指标与真实影响指标的关系要用小规模 A/B（故意降级模型）来测；金丝雀发布 + 快速回滚；训练/服务特征值必须一致。注意：只引 NIPS 2016 版；2017 IEEE 版改了计分（手动 0.5 分、自动 1 分、总分上限 7 分），未直读，不混用。
12. **小 benchmark 多次取平均，harness 的错公开说。**Gemini 3.1 Pro 方法论页（2026 年 2 月）：全部分数默认 pass@1（单次尝试，不许多数投票、不并行 test-time compute）；小 benchmark 多次试验取平均以减小方差；SWE-bench Verified 平均 10 次运行，SWE-bench Pro 平均 5 次；发现官方 harness 有 3 个 bug 导致任何解法都过不了，修后仅 Gemini 3.1 Pro Preview 自己的分数上调 0.6 个百分点，并在方法论页公开说明；MRCR v2 完整数据集公开以供复现。注意：非 Gemini 分数取自各厂商自报，各家脚手架与基础设施不同。

### 小样本统计

13. **小样本上不要用 CLT 算误差棒。**Bowyer 等（arXiv:2503.01747，ICML 2025 立场论文）：CLT 在只有几十到几百条样本的专用 benchmark 上系统性低估不确定性（误差棒太小、覆盖率达不到名义水平）；图 1 的 LangChain 20 题 benchmark 上 CLT 区间超出 [0,1] 或坍缩为零；推荐 Wilson 区间或贝叶斯可信区间。模拟实验：每个真值生成 N=3、10、30、100 的数据集，单模型 IID 场景共 80,000 个模拟 eval 数据集。注意：这是立场论文的主张，不是普适定理；N=100 时名义 95% 的 CLT 区间实际覆盖率 92.5%，低估幅度并不大，“系统性低估”在极小 N 时才剧烈。
14. **配对比较比独立比较灵敏得多。**Kinda Technical《配对比较》（2026-11-19）：200 题上 A 对 152、B 对 168（差 8 个百分点），不一致对 12 对 28。McNemar 精确检验 p=0.0166，卡方（带连续性修正）p=0.0177；而不配对的两比例 z 检验 p=0.0455。配对 bootstrap 得差值 8 个百分点，95% CI [2, 14]；不配对区间约 [0.2, 15.8]，几乎触零。连续分数情形 Wilcoxon p=0.0004 对 Welch p=0.1208（单源，未独立核实）。另：“只 6/200 题变了结果，任何检验都测不出什么”；“不要偷看再停”（每批都测、p 一低于 0.05 就停，会抬高假阳性）。
15. **有些检验绝不应使用。**Dietterich（1998）：两比例差检验和基于多次随机 train-test 切分的配对 t 检验第一类错误率很高，绝不应使用；10 折交叉验证配对 t 检验第一类错误率略高；McNemar 检验第一类错误率低；5×2cv 也可接受且比 McNemar 稍强；只能跑一次算法时，McNemar 是唯一可接受的检验；能跑 10 次时推荐 5×2cv。
16. **赢者诅咒：选出的最优者分数被高估。**Ribeiro《赢者诅咒》（2026-04-16）：100 个候选、1,000 条验证集时赢家高估 2.4 个百分点；200 条时 6.3 个百分点；k=100、n=1,000 时赢家真是最好配置的概率仅 16%。修正办法：留出测试集（选在验证集上、估计在测试集上）、嵌套交叉验证、收缩（经验贝叶斯）、报告全部候选分布。注意：2.4pp、16% 都是模拟条件数（真实准确率服从均值 80%、标准差 1 个百分点的正态分布、4,000 次重复、seed 0），不是普适常数——spread 为 0 时赢家真是最好配置的概率只有 1%，spread 为 3pp 时升至 58%；若候选真实准确率全相等，理论高估是 3.2pp 不是 2.4pp；留出测试集后测试集误差是无偏的，但仍有噪声（n=1,000 时标准误 1.3pp），“误差为 0”是四舍五入的模拟均值。
17. **多重比较：比较次数越多，假阳性越多。**m 次独立检验各在 α=0.05 下，至少一次假阳性的概率 = 1−0.95^m；12 个模型两两比较共 66 对，期望假显著 3.3 对。但 66 对两两比较并不独立（每对共享模型），把独立检验公式直接套上去，97% 这个数不成立——它只是独立情形下的算例，不是该场景的真实概率。Holm 逐步法在 FWER 拒绝力上不弱于 Bonferroni，但 Bonferroni 能直接给出同步置信区间，Holm 的相容同步区间构造困难，“永远优先”不是定理。
18. **功效：测出 0.02 的优势要多少样本。**两比例比较样本量公式 n ≈ (zα/2+zβ)²·[p1(1−p1)+p2(1−p2)] / (p1−p2)²；10% 基线 → 12% 目标（差 0.02），α=0.05 双侧、功效 80% 时每组约 3,834 题；5%→7% 约每组 2,207；5%→6% 约每组 8,146。（主 agent 自己用 Python 算了一遍，得 3,838 / 2,209 / 8,155，差异只是 z 取整。）

### 我们自己的换算（inference: 推导，不是来源断言）

19. inference: Wilson 区间：1/83 是 [0.2%, 6.5%]，23/83 是 [19.2%, 38.2%]，两者不重叠——公式确实比简单规则差，这是真差别；但 1/83 对 4/83（差 3.6pp）测不出来。
20. inference: 83 题上，独立比较能检出的差距约 10 个百分点（低基线）到 25 个百分点（中等基线）；配对比较看不一致对的数量——15 对、10 对 5 分时统计量 1.67，不显著；10 对、9 对 1 分时统计量 6.4，显著。
21. inference: 赢者诅咒在 4 个候选、83 题时：p=0.28 时赢家高估约 5.1pp，p=0.05 时约 2.5pp（按 Ribeiro 公式算）。但我们 4 路是真正不同的方法（不是近乎相同的配置），spread 大，诅咒比表里最坏的情况轻。
22. inference: CLT 区间：1/83 是 [-1.1%, 3.6%]（越出 0 下限，无效）；0/83 时标准误为 0，区间坍缩为零——我们之前报 0/83 时等于没给不确定性。

## 空地（8 条，一句话一条）

1. 前沿实验室选在一批题上、估在另一批题上；我们选和估都在同一批 83 题上。
2. 前沿实验室在同一批题上用配对检验比；我们比各自的准确率，从没用过配对结构。
3. 前沿实验室先量噪声再行动；我们从没量过自己的噪声。
4. 前沿实验室按最弱一环打分；我们只用猜中数这一项判好坏。
5. 前沿实验室先分类失败再动手改；我们 12 轮改了 12 次，从没把 82 次猜错按原因分过类。
6. 前沿实验室多路并行共享日志、赢一次就棘轮锁死；我们 4 路各自跑，没有共享记忆，也没有锁死机制。
7. 前沿实验室一个结论用三路不同方法各算一次；我们“谁最好”只由一个数字定。
8. 前沿实验室的 eval 是活的（加题、饱和的毕业）；我们的 83 题是死的，S6 到了也没有进 eval 的机制。

## 果实（按优先级，9 条）

### 果实 1：配对比较（空地 2）——最便宜，不用新数据

- 是什么：同一批 83 题上比两个 lane，不比各自的准确率。用 McNemar 精确检验 + 配对 bootstrap 报差值区间。
- 怎么用：每轮结束出一张配对表（不一致对：A 对 B 错几题、B 对 A 错几题）；只在 McNemar p<0.05 且配对 CI 不含 0 时才说“更好”。Dietterich 的话：只能跑一次时，McNemar 是唯一可接受的检验；两比例差检验绝不应使用。
- 怎么量它有没有效：看它改不改变决定——如果配对检验从没推翻过“比准确率”的结论，它就是多余的。
- 证伪：如果配对检验在 83 题上一次也没达到显著（不一致对太少），说明 83 题的配对结构里没有信号，这条果实作废。

### 果实 2：先量噪声（空地 3）——便宜

- 是什么：每轮开始前先测噪声底——把每个 lane 的预测重复跑 3 次，报 spread；改进小于噪声不算变好。
- 怎么用：Agent/NN 是非确定性的，重复跑才知道分数抖多少；公式是确定性的，spread 为 0。把“噪声”写进每轮报告的第一行。Anthropic hillclimb 的原话：开始前先验噪声，噪声须小于会采取行动的最小改进；增益在噪声内就说出来、建议不合并。
- 怎么量它有没有效：看它拦不拦得住假“变好”——如果某轮的改进小于噪声底，按规矩就不合并。
- 证伪：如果重复跑的 spread 全是 0（或远小于改进），噪声底可以忽略，这条果实作废。

### 果实 3：选与估分开（空地 1）——便宜，用现有数据

- 是什么：把 83 题切成两半：S4 选赢家，S5 估赢家的分数（或反过来）；赢家对外报的分数以估计集为准，不以选择集为准。
- 怎么用：锦标赛每轮在选择集上挑赢家，只在估计集上量赢家的真实分数；赢家的选择集分数只作参考，不作成绩。这是 hillclimb 的 train/test 分割、Lenny's 的判分器三切分、审计 agent 预先承诺评分标准的同一招。
- 怎么量它有没有效：看赢家的估计集分数比选择集分数低多少——如果低 2–5 个百分点，赢者诅咒真实存在；如果差不多，诅咒可以忽略。
- 证伪：如果赢家在估计集上的分数与选择集上的分数始终一致（差 <1pp），说明这里没有赢者诅咒，这条果实作废。

### 果实 4：最弱一环打分（空地 4）——便宜

- 是什么：每个 lane 按 6 项指标（猜中、血量方向、金币方向、段位、量级、校准度）各设一条及格线，总分取最弱一环；赢猜中数但校准度不及格的 lane 不通过。
- 怎么用：做一张 lane 记分卡，6 项全过才算“好”；锦标赛的晋级条件是“最弱一环变好”，不是“猜中数变好”。ML Test Score 的原话：总分取 4 个部分分数的最小值。
- 怎么量它有没有效：看它改不改变晋级——如果最弱一环的排名永远与猜中数排名一致，它就是多余的。
- 证伪：如果所有 lane 的 6 项指标高度相关（赢猜中数的总赢别的），最弱一环打分没有信息量，这条果实作废。

### 果实 5：先分类失败（空地 5）——便宜，是 agent 的活

- 是什么：下一轮动手改之前，先把 82 次猜错按原因分 ≤10 类、计数排序（Lenny's 的错误分析），打最大的一类。
- 怎么用：一个 agent 读 82 条猜错的记录（公式 + 当前最好 lane），逐条写原因，归纳成 ≤10 类，数每类几条；下一轮只针对最大的一类改。Anthropic hillclimb 的原话：停滞 2–3 轮后停下来，把剩余失败按原因分类——常能发现 eval 本身坏了。
- 怎么量它有没有效：看最大的一类占几成——如果最大的一类占 30% 以上，分类就有用；如果 82 条散成 30 多类、每类 1–2 条，分类没用。
- 证伪：如果猜错的原因分不出类（每类都只有 1–2 条），这条果实作废。

### 果实 6：报全部 lane + 赢家分数打折（空地 1）——便宜

- 是什么：每轮报告列出全部 4 路的分数，不只报赢家；赢家报的分数减去赢者诅咒的量（83 题、4 路时约 2–5 个百分点，按 Ribeiro 公式算）。
- 怎么用：批报告里加一张“全部 lane 分数表” + 一行“赢家打折后分数”；对外只报打折后的数。Ribeiro 的原话：不要把选出来的分数当估计值；报告全部候选分布。
- 怎么量它有没有效：看打折后赢家是不是还赢——如果打折后赢家变输家，说明原来的“赢”就是诅咒。
- 证伪：如果 4 路的分数 spread 本来就很大（赢家比第二名高 10pp 以上），打折不改变任何结论，这条果实作废。

### 果实 7：共享日志 + 棘轮（空地 6）——中等

- 是什么：4 路共享一份实验日志（每路的失败、改动、分数都写进去，别的路能读）；赢一次就锁死为新基线（棘轮），任何让基线回退的改动直接打回。
- 怎么用：runs/ 下面加一份 lanes 共享日志（每轮追加）；循环设计里加一条棘轮规则：新基线 = 估计集上最好的分数，只升不降。这是性能冲刺的“150 把锤子 + 一个 Slack 频道 + CI 棘轮”和自动审计 agent 的“共享实验日志跨 run 爬山”的同一招。
- 怎么量它有没有效：看别的路有没有用上共享日志里的发现——如果一轮里有 lane 明确写了“用了 X 路的失败记录”，日志就是活的。
- 证伪：如果三轮下来没有任何 lane 引用过别的 lane 的记录，共享日志是死重量，撤掉。

### 果实 8：三路印证 + 慢启动 bracket（空地 7）——中等

- 是什么：“谁最好”须三路检查一致才算数（估计集命中率 + 配对 McNemar + 另一切分或另一族指标）；锦标赛留一个不早淘汰的 bracket 给慢启动的 lane（Hyperband 式多 bracket）。
- 怎么用：晋级规则改成“三路里至少两路同意”；每批留一个 bracket，里面的 lane 第一轮不淘汰，第二轮再判。Chinchilla 的原话：三路不同方法估计同一最优前沿，结论一致才信。
- 怎么量它有没有效：看三路检查有没有分歧过——如果三路永远一致，其中两路是多余的；看慢启动 bracket 有没有 lane 在第二轮翻盘过。
- 证伪：如果三路检查永远一致、且从没有任何 lane 在第一轮差、第二轮好，这条果实作废。

### 果实 9：eval 是活的（空地 8）——中等

- 是什么：83 题不是终点——S6 的新轮次进来就加题；饱和的指标毕业（量级 91.88% 已近饱和，它主要是“猜小变化”，信号越来越少）。
- 怎么用：每次新赛季开赛，把新轮次的动作加进考题；每批检查一次各指标的饱和度，饱和的指标转回归套件（只防退化，不作晋级依据）。Anthropic 的原话：eval 到 100% 就只剩回归价值、没有改进信号；SWE-bench Verified 从 30% 起步，现 frontier 模型已近 >80% 饱和。
- 怎么量它有没有效：看新题加进来后 lane 排名变没变——如果新题从不改变排名，加题就是多余的。
- 证伪：如果 S6 迟迟不开赛、或新题与旧题完全同分布，加题机制永远触发不了，这条果实作废。
