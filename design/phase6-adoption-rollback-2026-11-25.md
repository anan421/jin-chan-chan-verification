## 0. 术语

- 增益：实验组平均分减对照组平均分。平均分指 3 批的平均分。审计后分数为准。
- 噪声带：同一方法 3 批分数的最大值减最小值。本轮噪声带以本轮对照组 3 批分数重算。
- 采用门槛：`max(11, 本轮噪声带)`。11 道是第 11 轮基线重测的噪声带（104 减 93）。
- 基线：对照组 C 使用的方法集合。基线版本号随采用与回滚而变。
- 暂定：方法未过采用门槛，但仍留在基线里。暂定不是采用。暂定不是丢掉。

## 1. 采用流程

采用流程一共 8 步。实验跑完后按顺序执行。任一步不通过，停下来。不进入下一步。

| 步 | 做什么 | 谁做 | 产出 | 通过标准 |
|---|---|---|---|---|
| 1 | 审计全部预测记录。查日期违规。查泄漏。查事实为空的记录 | 审计员 | 审计报告 | 审计覆盖全部记录。泄漏记录已排除。事实为空的记录已单独列出 |
| 2 | 两套独立打分脚本重算分数。先过复现门，再算本轮分数 | 打分员 | 两套脚本输出 | 两套输出逐项一致。复现门两关通过：复现基线平均 97.67 道、对照组平均 92.33 道、增益 +5.33 道；复现第 10 轮 32 道聚焦题对照组 31 道、实验组 32 道 |
| 3 | 算增益、噪声带、McNemar p 值。排除 39 道泄漏题后重算。列配对表。列增益来源 | 打分员 | 分数表与配对表 | 配对表四格齐全。增益来源分题列出。真新信息题数列出 |
| 4 | 对照协议第 6.1 节六个条件逐条判定。每条写通过或不通过，附数字 | 协调员 | 条件判定表 | 六条全部有数字证据。无一条凭印象判定 |
| 5 | 写采用决策记录。格式见第 2 节 | 协调员 | 采用决策记录 | 全部必填字段填满。无一字段空缺 |
| 6 | 第二人复核数字。复核人独立重算增益、噪声带、p 值 | 复核人 | 复核签字 | 复核人数字与第 3 步数字一致。不一致则返回第 2 步 |
| 7 | 做决策：采用、暂定、丢掉三选一。决策规则见第 1.1 节。决策后报告 Gu | 协调员 | 决策结论 | 决策与第 4 步判定表一致。决策结论写入采用决策记录 |
| 8 | 执行决策。采用则进基线。暂定则标暂定。丢掉则写原因。启动第 4 节监控 | 协调员 | 更新后的基线定义与方法文件清单 | 基线定义列出全部组件与版本号。方法文件清单写明采用轮次、增益、噪声带、p 值 |

### 1.1 决策规则

- 六个条件全部满足：采用。方法进基线。方法文件版本号加 1。基线版本号加 1。
- 任一条件不满足：不采用。方法标为暂定或丢掉，二选一。
- 暂定条件（三条同时满足，才可继续暂定）：增益为正，但未超噪声带。方法有真新信息（对照组三批全错、实验组全对的题大于等于 2 道）。方法无系统性帮倒忙。
- 丢掉条件（满足任一条，丢掉）：增益为 0 或为负。增益只来自泄漏题。方法在新种类上帮倒忙。方法无真新信息。
- 采用门槛不因复测而降低。第 12 轮复测不过，采用门槛不变。

### 1.2 采用后的基线更新

- 采用的方法写进基线定义。基线定义列出全部组件与版本号。
- 采用的方法写进方法文件清单。清单写明每个方法的采用轮次、增益、噪声带、p 值。
- 采用不等于永久。采用后的方法在后续轮次与 S6 实盘上继续量分。后续量分触发回滚条件，执行第 3 节回滚流程。

## 2. 采用决策记录格式

### 2.1 字段表

| 字段 | 必填 | 说明 |
|---|---|---|
| 方法名 | 是 | 方法文件的方法名。写全名 |
| 实验轮次 | 是 | 轮次编号。如第 11 轮 |
| 实验组平均分 | 是 | 3 批审计后平均分。单位：道 |
| 对照组平均分 | 是 | 3 批审计后平均分。单位：道 |
| 增益 | 是 | 实验组平均分减对照组平均分。单位：道 |
| 本轮噪声带 | 是 | 本轮对照组 3 批分数的最大值减最小值。单位：道 |
| 采用门槛 | 是 | `max(11, 本轮噪声带)`。单位：道 |
| 是否过门槛 | 是 | 增益严格大于采用门槛，才写是。增益等于门槛，写否 |
| McNemar p 值 | 是 | 双侧检验 p 值。显著性水平 0.05。未做检验，写未做并写原因 |

| 最弱项变化 | 是 | 实验组最弱种类命中率与对照组最弱种类命中率。写两个数字 |
| 泄漏排除后增益 | 是 | 排除 39 道泄漏题后重算的增益。单位：道 |

| 决策 | 是 | 采用、暂定、丢掉三选一 |

## 3. 回滚流程

回滚流程一共 6 步。触发回滚条件时按顺序执行。触发条件见协议第 7.1 节。满足任一条，执行回滚。

| 步 | 做什么 | 谁做 | 产出 |
|---|---|---|---|
| 1 | 发现触发信号。信号来自第 4 节监控，或审计发现泄漏，或复现门失败 | 监控员或审计员 | 触发信号记录。写明信号来源、日期、数字 |
| 2 | 核验触发条件。对照协议第 7.1 节五条逐条核对。写证据 | 协调员 | 触发核验表。每条写触发或未触发，附证据数字 |
| 3 | 停用该方法。基线恢复到采用前的版本。基线版本号回退。回退记录写入基线定义 | 协调员 | 更新后的基线定义。回退记录写明回退前版本与回退后版本 |
| 4 | 写回滚报告。报告写明触发条件、证据、回滚前后的基线版本、受影响的分数 | 协调员 | 回滚报告 |
| 5 | 受影响的预测重新量分。重新量分用回滚后的基线。重新量分的结果单独报告 | 打分员 | 重新量分报告。结果单独列出，不与原分数混算 |
| 6 | 归档并报告 Gu。定方法回滚后的状态。状态规则见第 3.1 节 | 协调员 | 归档记录。方法状态写入方法文件清单 |

### 3.1 基线如何恢复到采用前的版本

- 基线定义须保存每次采用前的版本快照。快照写明组件清单与版本号。
- 回滚时，协调员取采用前的快照。基线组件恢复为快照内容。基线版本号回退到快照的版本号。
- 方法文件版本号同步回退。回退后的方法文件版本号等于采用前的版本号。
- 回滚不改冻结赛季。回滚不改结算口径。回滚不改事实。涉及改冻结赛季、改结算口径、改事实的回滚，须先报 Gu 确认再执行。
- 回滚不删除历史记录。采用记录、回滚记录、分数记录全部保留。删除历史记录须 Gu 批准。

### 3.2 回滚后方法的状态

- 回滚后方法的状态是丢掉或暂定，二选一。规则由触发条件决定。本规则由本文件定。协议第 7 节未写该映射。
- 触发一（S6 量分集分数低于对照组）：丢掉。增益为负，符合协议第 6.2 节丢掉条件。
- 触发二（连续两轮增益为负）：丢掉。增益为负，符合协议第 6.2 节丢掉条件。
- 触发三（最弱项跌幅大于 10 个百分点）：丢掉。方法使最弱项系统性变差。
- 触发四（依赖泄漏）：丢掉。增益只来自泄漏题，符合协议第 6.2 节丢掉条件。
- 触发五（复现门失败，分数算错）：暂定。分数算错不等于方法无效。打分脚本修好后重算。重算后重新判定。重算仍不过，丢掉。

### 3.3 假设例子

- 假设：某方法在第 12 轮采用。采用时增益 +13 道。噪声带 11 道。采用门槛 11 道。p 值 0.03。六条件全部通过。
- 假设：S6 新题 30 道结算后，该方法在 S6 量分集上的审计后平均分低于对照组 2 道。
- 判定：触发协议第 7.1 节触发一。S6 量分集分数低于对照组。
- 执行：第 3 步停用该方法。基线恢复到第 12 轮采用前的版本。基线版本号回退。方法文件版本号回退。
- 报告：第 4 步写回滚报告。报告写明触发一、S6 分数差 -2 道、回滚前后的基线版本。
- 重新量分：第 5 步用回滚后的基线重算受影响的预测。结果单独报告。
- 状态：第 6 步定状态为丢掉。触发一对应丢掉。方法不进基线。方法文件清单写明丢掉原因：S6 新题上低于对照组 2 道。
- 注意：本例是假设。数字是构造的例子。数字不是真实分数。

## 4. 监控触发器

### 4.1 监控什么

- 采用后的方法在每一轮的增益。增益指实验组平均分减对照组平均分。
- 采用后的方法在 S6 量分集上的分数。分数指审计后平均分。
- 采用后的方法的最弱项命中率。最弱项指命中率最低的种类。
- 打分脚本的复现门状态。复现门每轮跑一次。
- 方法文件的泄漏状态。审计每轮查一次。

### 4.2 检查频率

- 每一轮跑完检查一次。检查覆盖增益、最弱项、复现门、泄漏。
- S6 实盘每结算一批检查一次。检查覆盖 S6 量分集分数。
- 单批分数波动不触发回滚。单批分数低于对照组，但 3 批平均分不低于对照组，不回滚。
- 单种类题数少于 5 道，该种类分数波动不触发回滚。

### 4.3 触发器表

触发器一共 7 个。2 个触发复核。5 个触发回滚。全部是数字。无一条凭感觉。

| 编号 | 触发器 | 数值 | 动作 |
|---|---|---|---|
| M1 | 单轮增益小于 3 道 | 增益 < 3 道 | 复核。协调员复核分数与配对表。复核后决定是否提前复测 |
| M2 | 最弱项命中率跌幅大于 5 个百分点 | 跌幅 > 5 个百分点 | 复核。协调员复核最弱项分项分数。复核后决定是否提前复测 |
| M3 | S6 量分集分数低于对照组 | S6 平均分 < 对照组平均分 | 回滚。协议第 7.1 节触发一 |
| M4 | 连续两轮增益为负 | 增益 < 0 道，连续 2 轮 | 回滚。协议第 7.1 节触发二 |
| M5 | 最弱项命中率跌幅大于 10 个百分点 | 跌幅 > 10 个百分点 | 回滚。协议第 7.1 节触发三 |
| M6 | 发现方法依赖泄漏 | 泄漏 1 处 | 回滚。协议第 7.1 节触发四 |
| M7 | 打分脚本复现门失败 | 复现门 2 关中任一关失败 | 回滚。协议第 7.1 节触发五 |

### 4.4 触发器说明

- M1 与 M2 是本文件定的复核线。协议第 7 节只写回滚条件，未写复核线。复核线须协调员确认。
- M3 至 M7 直接来自协议第 7.1 节。数字与协议一致。
- M4 的连续两轮指两个独立轮次，不指同一轮次的两批。
- M6 的泄漏指方法文件里的例子是题集原题，或预测员的事实就是本题事件。
- 复核不等于回滚。复核后方法继续留在基线里。复核只决定是否提前复测。

## 5. 暂定状态管理

暂定管理规则一共 5 条。

| 编号 | 规则 | 内容 |
|---|---|---|
| R1 | 暂定方法留在基线里 | 暂定方法进基线工作版。方法文件清单里标暂定，与已采用方法分开列。暂定方法不触发基线版本号加 1。已采用方法触发基线版本号加 1 |
| R2 | 暂定方法的权重与已采用方法相同 | 预测员同等执行暂定方法与已采用方法。权重无区别。区别只在状态、版本号与复测义务。暂定方法须在方法文件清单里标明暂定状态，预测员须知道自己用的方法是暂定方法 |
| R3 | 暂定方法下一轮必须复测 | 暂定方法在下一轮复测。复测用 S6 新题。复测周期是一轮。暂定方法不复测，不得转正 |
| R4 | 复测不过的处理 | 复测增益为正、未过门槛、有真新信息大于等于 2 道、无系统性帮倒忙：继续暂定一轮。复测增益为 0 或为负，或无真新信息，或在新种类上帮倒忙：丢掉。连续两轮复测不过：丢掉，不再继续暂定 |
| R5 | 复测轮方法文件锁定 | 量分集锁定后，方法文件不得再改。方法文件改动会污染量分集。复测轮发现方法文件仍有泄漏，停跑。修好后重跑。重跑的分数不与停跑前的分数混算 |

- 两个方法复测前不转正。复测不过，采用门槛不变。复测不过，不降低门槛。
